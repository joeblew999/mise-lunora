## Templates `lunora init` offers

`-t`: analog, astro, expo, next, nuxt, rspack-react, solid-v2, standalone, sveltekit,
tanstack-start-react, tanstack-start-react-rspack, tanstack-start-solid, vinext, vinext-pages.
`--vite`: react, vue, solid, svelte, vanilla. No `-t` gives the Vite + React app above.

Also tried once, not kept in the repo:

- `standalone` (Worker only, no frontend): install, codegen, `pnpm dev`, write and read all OK.
- `tanstack-start-react`: install and codegen OK. Codegen warns about the template itself:
  `vite.config.ts` sets `allowUnauthenticatedShardAccess: true` with no row-level security,
  so an anonymous caller could read another tenant's rows. Fix before using it for real.

## Order, and why

Worked out by running `examples/app` from a clean checkout (`git clean -xdf`) and skipping steps on purpose.

1. `app:install`: everything else needs `node_modules`.
2. `app:generate`: `build` fails without `lunora/_generated` (`Cannot find module '../lunora/_generated/app.js'`).
3. `app:verify`: passes even with no generated code (its codegen runs in memory and writes nothing),
   so it is no proof the app builds. Run it after generate, before build.
4. `app:build`
5. `app:check`: starts the dev server, waits for `GET /` to return 200, stops it. Full chain from a
   clean checkout: 26 s.

Also found:

- `pnpm dev` runs codegen itself, so `app:serve` only needs install.
- Local data lives in `.wrangler/` (gitignored). A clean checkout starts with empty data.
- The dev server writes `.dev.vars` with a random local `LUNORA_ADMIN_TOKEN` for Lunora Studio (gitignored).
