## Order, and why

`mise run apps:verify` runs the same chain on every app in `examples/`, one at a time:
`examples/vite-react` (default template) and `examples/tanstack-start-react`. Both pass.

Worked out by running from a clean checkout (`git clean -xdf`) and skipping steps on purpose.

1. `app:install`: everything else needs `node_modules`.
2. `app:generate`: `build` fails without `lunora/_generated` (`Cannot find module '../lunora/_generated/app.js'`).
3. `app:build`: also writes framework files. TanStack Start's `routeTree.gen.ts` only exists after
   build or dev, so type-checking before build fails (`Cannot find module './routeTree.gen'`).
4. `app:verify`: after build. It passes even with no generated code (its codegen runs in memory and
   writes nothing), so on its own it is no proof the app builds.
5. (Removed) `app:check` started the dev server, waited for a 200, and stopped it. Stopping a
   background server reliably on Linux and Mac was the fragile part: one version used Linux-only
   `setsid`, the next left both servers running. The "does it really run" proof moves to deploy
   (request the live URL), which needs no local server.

Time per step, vite-react, already installed: install 0.7 s, codegen 3.7 s, verify 4.2 s,
build 9.6 s, dev server up 7.2 s. Whole chain with the dev-server check: vite-react 25 s, tanstack-start-react 48 s.

Also found:

- `pnpm dev` runs codegen itself, so `app:serve` only needs install.
- Local data lives in `.wrangler/` (gitignored). A clean checkout starts with empty data.
- The dev server writes `.dev.vars` with a random local `LUNORA_ADMIN_TOKEN` for Lunora Studio (gitignored).
- mise `[env]` values override the shell, so `APP` and `TEMPLATE` use `get_env(...)` to let a shell value win.
- The tanstack-start-react template sets `allowUnauthenticatedShardAccess: true` with no row-level
  security; Lunora's own codegen warns about it.
